# 저장 방식 · 1.10.0

GUI는 목록 전체를 처리합니다. 파일을 추가하거나 목록을 비우면 지원 범위를 다시 계산합니다. 지원하지 않는 방식은 선택할 수 없으며 '사용 불가' 표시와 저장 방식 옆 ⓘ에서 현재 목록의 제한 이유를 설명합니다. 기존 선택이 지원되지 않으면 사용 가능한 첫 번째 방식으로 변경하며, 현재 방식과 사용 불가 항목을 선택란 아래에 표시합니다.

| 방식 | 현재 지원 | 출력 |
| --- | --- | --- |
| 1. 원본 형식 유지 | 호환 JPEG SVS·NDPI, Philips iSyntax/i2syntax | `.svs` / `.ndpi` / `.isyntax` |
| 2. TIFF 변환 · 원본 압축 유지 | 호환 JPEG 구조의 SVS·NDPI·TIFF | `.tiff` |
| 3. TIFF 변환 · 무손실 압축 | 프로그램에서 읽을 수 있는 입력 | JPEG 2000 무손실 `.tiff` |

1번은 실제 원본 컨테이너 구조와 조직 압축을 유지합니다. SVS·NDPI의 기술 정보와 파일 인덱스를 새로 작성하고 원본 개인정보 메타데이터와 부속 이미지는 제외합니다. OpenSlide에서 Aperio SVS / Hamamatsu NDPI로 인식하는지 검증합니다. Philips `.i2syntax`도 `.isyntax`로 저장하며 일반 OpenSlide에서는 읽을 수 없습니다. 지원하는 세부 레이아웃은 [SVS·NDPI 원본 형식 안내](native_svs_ndpi.md)를 참고하세요.

2번은 원본 최대 해상도 JPEG 코딩 데이터를 재사용합니다. 파일 크기나 압축률까지 같아지는 것은 아니며, 작은 축소 레벨은 새로 생성할 수 있습니다. Philips 고유 압축은 OpenSlide 호환 TIFF에 재사용할 수 없어 2번이 비활성화됩니다. TIFF 헤더의 압축·타일 구조를 사전 확인하며 실제 데이터 유효성은 내보내기에서 최종 검증합니다.

3번은 **모든 입력**에 JPEG 2000 무손실 압축을 적용합니다. 읽어낸 최대 해상도 RGB 픽셀을 보존하지만 과거의 손실 압축을 복구하지 않습니다. 피라미드 축소 레벨은 리사이즈됩니다. 용량과 처리 시간이 크게 늘어날 수 있습니다. 읽기 불가능하거나 손상된 입력은 검사/내보내기에서 오류로 표시합니다.

호환 SVS·NDPI·Philips는 한 목록에서 1번으로 각 원본 형식을 유지할 수 있습니다. 일반 TIFF와 Philips를 함께 추가하면 1·2번은 사용할 수 없고 3번이 선택됩니다. CSV만 선택하면 저장 방식은 비활성화됩니다.

1번의 Python API는 `compression="native"`, 2번은 `compression="preserve"`, 3번은 `compression="jpeg2000"`입니다. 기존 Philips 전용 `philips`, `lossless`(Deflate), `jpeg`(손실 JPEG)도 API에서 계속 사용할 수 있습니다.
