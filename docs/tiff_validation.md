# 이전 피라미드 TIFF 검증 기록 (v2) — 2026-09-08

현재 단일 영상 출력의 검증은 [단일 TIFF + CSV 기록](single_tiff_validation.md)을 참고하세요.

이 PC의 `yslee` 환경에서 실제 샘플 전체를 변환한 1회 실행 결과입니다. 모든 입력 픽셀을 디코딩하고 새 Deflate 스트림으로 기록했습니다.

| 항목 | SVS 입력 | NDPI 입력 |
|---|---:|---:|
| 입력 용량 (십진 GB) | 1.12 | 2.11 |
| 출력 용량 (십진 GB) | 7.02 | 29.52 |
| 영상 레벨 | 3 | 8 |
| 최대 영상 크기 | 110,562 × 61,468 | 126,720 × 96,768 |
| 전체 출력 타일 검증 | 27,922개 통과 | 62,628개 통과 |
| 변환 및 검증 소요 시간 | 290.2초 | 753.3초 |
| 원본 전체 SHA-256 | 작업 전후 동일 | 작업 전후 동일 |

출력은 `output/clean_tiff/`에 있으며 결과 JSON은 `artifacts/full_tiff_validation.json`에 있습니다. 두 경로는 Git에서 제외합니다. 자동 테스트가 실제 조직 영상 전체의 개인정보를 판정한 것은 아니므로 두 결과 모두 `metadata_clean_pixel_review_required` 상태입니다.

출력에서는 구조 태그 허용 목록과 문자열 태그 부재를 검사하고, OpenSlide로 일반 TIFF 인식·영상 레벨·부속 이미지 부재를 확인했습니다. 원본 ICC, 전용 태그, 부속 이미지 및 원본 압축 바이트는 복사하지 않았습니다.

독립 파일 단위 테스트 6개도 통과했습니다: 모든 레벨의 좌표 마스크와 비마스크 픽셀 보존, 메타데이터/미참조 식별 문자열 제외, 취소 정리, 기존 파일 보호, 검증 오류 파일의 게시 방지, 저장 중 다른 프로세스가 만든 파일 보호 및 프로젝트 밖 독립 실행을 포함합니다.

GUI에서는 두 실제 샘플의 검사와 썸네일 표시를 확인하고, 작은 TIFF로 실제 내보내기·픽셀 검토 상태 전달·중지 정리·잘못된 출력 경로/손상 파일 오류 복구를 확인했습니다.

원본이 손실 JPEG 압축일 때 무손실 TIFF는 훨씬 커질 수 있습니다. 이 소요 시간과 압축률은 해당 샘플과 PC의 관측값이며 다른 파일에 대한 성능 보장은 아닙니다.
